A least-privilege audit can use NSS and account-management commands without directly opening `/etc/shadow` or printing password hashes.

```sh
# Enumerate passwd records via NSS
getent passwd

# Query one account
getent passwd -- username
```

Reveals `name:x:UID:GID:GECOS:home:shell`. The `x` is only a placeholder; no password hash is returned. `getent passwd` may include LDAP/SSSD/NIS accounts, not only local accounts. For local `/etc/passwd` records through NSS:

```sh
getent -s files passwd
```

```sh
# Show status for one account
passwd -S -- username

# Show accounts whose password state is not usable
passwd -Sa | awk '$2 != "P" { print $1 "\t" $2 }'
```

Status meanings commonly include `P` usable password, `L` locked password, and `NP` no password. `passwd -S` may consult the shadow backend internally; it does not print hashes. A normal user may only be allowed to inspect their own account. Use narrowly delegated privilege only if system-wide results are required.

```sh
# Show password-aging and account-expiration policy
chage -l -- username
```

Reveals last password change, password expiration, inactivity, account expiration, minimum age, maximum age, and warning period. It does not display the password hash. System-wide inspection generally requires privilege and should be delegated only for this command and specific account arguments.

Safe aggregate checks:

```sh
# Accounts with UID 0
getent passwd | awk -F: '$3 == 0 { print $1 }'

# Accounts using login-capable shells
getent passwd | awk -F: '$7 !~ /(^|\/)(false|nologin)$/ { print $1 "\t" $3 "\t" $7 }'

# Accounts below the configured system UID threshold
uid_min=$(awk '$1 == "UID_MIN" { print $2; exit }' /etc/login.defs)
getent passwd | awk -F: -v min="${uid_min:-1000}" '$3 < min { print $1 "\t" $3 "\t" $7 }'

# Duplicate UIDs
getent passwd | awk -F: '{ count[$3]++; names[$3] = names[$3] " " $1 } END { for (uid in count) if (count[uid] > 1) print uid names[uid] }'
```

Avoid `getent shadow`, `sudo cat /etc/shadow`, `unshadow`, debugging traces, and unrestricted root access. These commands may expose hashes or other credential material.
