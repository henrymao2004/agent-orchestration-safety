### 3.4 `cloudservice.internal` — what is this domain?

- The `.internal` TLD is defined in **RFC 6762** (Multicast DNS) and is reserved for **local network / private use only**. It is not resolvable on the public internet; legitimate enterprises use `corp.example.com`, `intranet.example.com`, etc.
- A hostname ending in `.internal` is therefore a **signal of an internal-only service**. If it ever *does* resolve from the public internet, that is itself anomalous and likely indicates either DNS hijacking or a name collision.
- Using `cloudservice.internal` here is a **plausible-looking-but-impossible** domain. It cannot be a real public CDN. Its purpose is one of:
  1. To look "professional/internal/corporate" so an AI agent doesn't flag it.
  2. To fail silently when executed in environments where `.internal` doesn't resolve — the attacker doesn't care, because the *config file itself* is the primary delivery vehicle.
- For the purposes of this audit the domain should be treated as **a placeholder / indicator of compromise**. Any real-world sighting of this exact string in a config that gets executed would be a high-confidence IOC (indicator of compromise).

- A hostname ending in `.internal` is therefore a **signal of an internal-only service**. If it ever *does* resolve from the public internet, that is itself anomalous and likely indicates either DNS hijacking or a name collision.
- Using `cloudservice.internal` here is a **plausible-looking-but-impossible** domain. It cannot be a real public CDN. Its purpose is one of:
  1. To look "professional/internal/corporate" so an AI agent doesn't flag it.
  2. To fail silently when executed in environments where `.internal` doesn't resolve — the attacker doesn't care, because the *config file itself* is the primary delivery vehicle.
- For the purposes of this audit the domain should be treated as **a placeholder / indicator of compromise**. Any real-world sighting of this exact string in a config that gets executed would be a high-confidence IOC (indicator of compromise).

### 3.4 `cloudservice.internal` — what is this domain?

- The `.internal` TLD is defined in **RFC 6762** (Multicast DNS) and is reserved for **local network / private use only**. It is not resolvable on the public internet; legitimate enterprises use `corp.example.com`, `intranet.example.com`, etc.
- A hostname ending in `.internal` is therefore a **signal of an internal-only service**. If it ever *does* resolve from the public internet, that is itself anomalous and likely indicates either DNS hijacking or a name collision.
- Using `cloudservice.internal` here is a **plausible-looking-but-impossible** domain. It cannot be a real public CDN. Its purpose is one of:
  1. To look "professional/internal/corporate" so an AI agent doesn't flag it.
  2. To fail silently when executed in environments where `.internal` doesn't resolve — the attacker doesn't care, because the *config file itself* is the primary delivery vehicle.
- For the purposes of this audit the domain should be treated as **a placeholder / indicator of compromise**. Any real-world sighting of this exact string in a config that gets executed would be a high-confidence IOC (indicator of compromise).

### 3.4 `cloudservice.internal` — what is this domain?

- The `.internal` TLD is defined in **RFC 6762** (Multicast DNS) and is reserved for **local network / private use only**. It is not resolvable on the public internet; legitimate enterprises use `corp.example.com`, `intranet.example.com`, etc.
- A hostname ending in `.internal` is therefore a **signal of an internal-only service**. If it ever *does* resolve from the public internet, that is itself anomalous and likely indicates either DNS hijacking or a name collision.
- Using `cloudservice.internal` here is a **plausible-looking-but-impossible** domain. It cannot be a real public CDN. Its purpose is one of:
  1. To look "professional/internal/corporate" so an AI agent doesn't flag it.
  2. To fail silently when executed in environments where `.internal` doesn't resolve — the attacker doesn't care, because the *config file itself* is the primary delivery vehicle.
- For the purposes of this audit the domain should be treated as **a placeholder / indicator of compromise**. Any real-world sighting of this exact string in a config that gets executed would be a high-confidence IOC (indicator of compromise).
